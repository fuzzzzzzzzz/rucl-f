# 低成本存储替代方案：待验证

## 已核实

- 当前远端存储回读仍为 PRIVATE，未修改线上配置。
- 客户端的存放照片、交接证明调用 uploadPrivateImage，由 api 云函数上传。
- 本地新版 OCR 原图已经改为 Base64 内存直传，不调用客户端云存储上传；线上旧版尚未替换。
- 图片访问已有服务端临时链接路径，仍须逐项检查授权与链接有效期。
- 所有旧工作树和未提交修改保留。

## 替代目标

评估以基础 ADMINONLY 存储权限配合服务端鉴权替代 CUSTOM。不把 PRIVATE 当作等价方案，不公开照片，不购买套餐。当前套餐是否允许设置 ADMINONLY 尚未通过实际变更验证。

官方依据：https://docs.cloudbase.net/storage/data-permission

## 已选定的 OCR 传输方向

官方微信小程序调用示例明确标注 `wx.cloud.callFunction` 的 data 上限为 5 MB：
https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram

采用至多 2 MiB JPEG/PNG 的 Base64 直接调用（编码后约 2.67 MiB），不分片、不保存 OCR 原图到云存储。保留当前预处理清晰度，超过上限明确要求重拍或手动填写，不静默降低画质。客户端和服务端均限制大小；服务端检查严格 Base64、JPEG/PNG 文件头和一次性上传凭证的归属、过期、消费状态；图像是否可解码由 OCR 服务最终确认。旧版 fileId 入口在过渡期间继续兼容，两种入口均检查当前账号状态。

此上限依据不同于通用 HTTP 错误页的“文本 100KB／其他 6MB”，不能混用。最终仍必须在目标环境用真机验证接近上限的图片传输及识别。

OCR 原图只在处理期间存在于客户端和服务端内存，不需要上传到存储。现有存放照片和交接证明仍走服务端上传。实施完成后可继续验证 ADMINONLY 基础权限，尚不切换线上权限。

## 实施前必须解决

1. 核实微信云函数实际调用通道的请求大小限制。不要直接假设可以一次传入数 MB Base64；不要为了适配限制过度压缩 OCR 原图。
2. 选择经验证的服务端上传传输方案。若分片，必须有用户绑定、总量限制、分片数量限制、过期清理、幂等、完整性校验及并发控制，不能把临时数据留在业务日志。
3. 保留现有 OCR 身份校验、限流、上传凭证一次性消费和失败清理；服务端上传不能仅信任客户端 fileId 或文件路径。
4. 补齐匿名、停用账号、跨账号凭证、重复请求、损坏图片、弱网重试和上传中断的行为测试，再实现。
5. 完成新开发版上传、OCR 清晰度和照片预览的真机测试后，安排维护窗口切换 ADMINONLY。必须有可执行回滚方案并验证权限回读。
6. 更新基础设施契约、部署检查及提审证据，不能删掉安全门禁来制造通过。

## 当前结论

本地 OCR 传输改造和 ADMINONLY 目标契约已实现，相关回归测试通过。当前远端仍为 PRIVATE，没有部署新函数、上传新开发版或切换权限。尚未证明当前套餐允许应用 ADMINONLY，也未完成接近 2 MiB 的真机传输验收。不能承诺永久零费用；存储、流量、云函数及 OCR 仍消耗额度。此文不是提审通过证据。

资源部署新增维护确认门禁：必须显式设置 STORAGE_MAINTENANCE_CONFIRMED=yes，并在首次远端操作前检查；缺失时停止。只在新版真机验收、用户切换及回滚准备完成后设置，不能为通过脚本而跳过真实验收。
