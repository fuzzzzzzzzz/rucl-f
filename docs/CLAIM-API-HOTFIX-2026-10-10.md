# 认领提交接口热修复（2026-10-10）

真机查询已能找到卡片，但确认认领弹出 `-604100 API not found`。云端记录与审计证明申请已保存，日志同时记录了微信 OpenAPI 调用异常，以及一次 15 秒超时。

根因：`runtimeProxy` 对函数调用 `.bind(target)`，但 `wx-server-sdk@4.0.2` 的 `cloud.openapi` 是可调用代理，根代理的 `.bind` 属性被解析为接口路径 `bind`。读取这个属性会启动无效微信接口请求；业务事务已经提交，随后这个额外请求导致报错或超时。

修正：包装运行时属性时直接返回 `openapi` 代理，其余方法保持原有绑定方式。

验证：新增认领通知行为回归，修复前断言收到 `bind` 而失败，修复后正确请求 `subscribeMessage.send`；后端、通知重试、内容安全相关 137 项测试通过。云端类型检查、相关 ESLint 与 diff 检查通过。

上线方式：下载当前 API 到私有 `.release-evidence/claim-api-before-20261010` 作为回退包，复制到热修复目录，只增加注释与 `openapi` 原样返回判断，再通过 `fn code update` 更新 API 代码。当前开发分支的其他后台功能没有纳入此次热修复。

部署验证：2026-10-10 00:17:23（北京时间）更新成功；函数回读为 `Active / Available`，环境变量指纹、运行时、权限角色、超时、内存及入口配置均未改变。热修复目录与备份的 6856 个文件中仅 `handler.js` 不同；重新下载的线上 `handler.js` 与修复包 SHA-256 一致。

最终手机端确认提示仍需用户测试。既有认领申请保持实际状态，不代替管理员审批或确认交还。申请已保存，用户可重新进入「MY → 我的认领」查看待核对状态，无需再次提交。
