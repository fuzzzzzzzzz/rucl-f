# 内容安全：实现边界与验收位置

更新时间：2026-09-17。此文件不是接口成功回执，也不代表可以提审。

## 已确认的问题

已上传的 0.6.1 仅对感谢文字调用 `msgSecCheck`。姓名、发布地点等其他文字及上传照片没有完整的审核链路。后台勾选“使用平台建议的内容安全 API”不能作为这些链路已通过验证的证据。

本轮文字修复的范围：

| 入口         | 待检查的实际内容                         | 检查时机                                                     |
| ------------ | ---------------------------------------- | ------------------------------------------------------------ |
| 我的信息     | 姓名                                     | 写入身份摘要前                                               |
| 发布招领     | 姓名、拾取及存放地点的四个字段、私密特征 | 消耗照片令牌、写入记录、发送通知前                           |
| 登记失卡     | 地点描述、私密特征                       | 写入记录前                                                   |
| 转交官方地点 | 存放地点的四个字段                       | 消耗照片令牌或更改记录前                                     |
| 交接感谢     | 用户选择填写的感谢文字                   | 只允许通过审核的文字进入消息或感谢墙；文字被拒不撤销有效交接 |

不向内容检查接口发送学号、上传令牌或记录 ID。举报、投诉、反馈、身份更正原因和删除申请属于受限的管理处理渠道，不因机器审核不可用而拒收；它们不是公开内容流，也不据此声称已实施人工预审。管理员自由文字回复及既有历史内容不属于本轮新增入口检查的覆盖范围。

## 图片审核的外部前提

现行 [多媒体内容安全接口文档](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_mediacheckasync.html) 定义的是 `security.mediaCheckAsync` v2：提交返回任务标识，最终结果通过消息推送返回，可能等待 30 分钟。旧版同步接口已停止更新。本轮不采用推测可用的旧接口，也不擅自开通收费审核产品。

完整实现必须包括：

- 可验证来源的结果接收端；不能把普通客户端传入的 `pass` 当成微信审核结果。
- 待审核、通过、拒绝/异常状态与文件绑定，处理重复通知、乱序、失败和超时。
- 消耗上传令牌和返回图片链接前检查最终结果；旧图片需另有明确迁移策略。
- 同步调整客户端等待/重试流程以及文件过期清理，不能把检测任务创建成功当作图片通过。
- 不降低 OCR 原图清晰度来适配旧接口，不把 OCR 文字识别等同于图片内容审核。

当前项目没有上述回调接收端。必须先确认现有消息推送配置，不能覆盖未知的原有配置或新增收费资源。官方 [消息推送说明](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push.html) 对云函数接收范围另有说明，不能仅因环境具有云函数就假定能接收此审核事件。

- 尚未创建路由、启用服务、绑定域名或配置消息推送。下一步需确认用户是否已有可复用的 HTTPS 服务和已备案域名；若没有，需先确定并授权接收服务的成本与部署方式，不能默认为允许购买或引入第三方数据处理服务。

1. **消息推送配置**：左侧“开发与服务” → “开发管理” → 顶部“开发设置” → 页面中的“消息推送配置”。需要配置状态与接收方式；截图遮住 Token、EncodingAESKey 等密钥。若没有此栏目，提供当前页面栏目截图，不随意更改其他安全设置。
2. **隐私与 UGC 保存状态**：左下角账号“佧了” → “账号设置” → “基本信息”页向下找到“服务内容声明”。分别查看“用户隐私保护指引”和“用户生成内容场景声明”的状态。用户已报告完成填写，但完整最终生效回执仍需留存。
3. **搜索限制原因**：左侧“成长” → “违规记录”，查看与“被搜索功能已被限制”对应的具体通知。不能把未认证或云套餐当作已经查明的原因。
4. **订阅模板**：核对实际选用模板的 `thing1`、`thing2` 字段含义与项目通知内容一致。只提供字段含义，不粘贴密钥。
5. **密钥轮换**：只确认曾暴露凭据的轮换日期和完成状态，不上传新旧凭据。

## 验证规则

单元测试的模拟审核结果只能证明应用处理结果的逻辑，不能证明账号 API 权限可用。发布守卫上线前，需使用近期访问过小程序的测试账号取得真实 API 成功证据。现行 [文字接口文档](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_msgseccheck.html) 要求 OpenID 对应用户最近两小时访问过小程序；不能凭空伪造 OpenID，也不能将匿名云函数试调用的失败当成正常业务验收。

启用新增文字检查前还须同步告知：已上传的旧开发包只写了感谢文字审核。本地隐私页已增加姓名、地点和私密特征的检查范围，并实现逐次明确同意弹窗和服务端协议版本检查；缺少新版标记的旧客户端不能进入新增检查。后台“开发者处理的信息”对应用途、补充说明仍须同步保存并确认生效。未完成前不得把本轮服务端代码直接部署到共用环境；版本检查会阻止旧客户端的四类写操作，需要协调客户端更新。

在外部前提、部署和回读均未完成前，继续保留阻断状态，不改写旧开发版上传回执、不提交审核、不切换线上 PRIVATE 存储权限。
