# 发布硬门禁

以下项目未全部人工确认时，不得把 `0.6.1` 上传为正式版或提交审核。本轮只允许上传开发版，不执行微信公众平台最终审核。

## 代码门禁与提审证据门禁

`npm run verify` 验证本地代码；`npm run release:check` 仅验证开发通知目标配置，两者均不单独代表可以提交审核。

完整证据汇总后运行 `npm run review:check -- --evidence=.release-evidence/review.json`。该门禁要求工作树干净，证据的提交号、0.6.1版本、环境与目标一致，并逐项检查本地门禁、安全审计、Windows/Linux CI、最终真机验收、云端权限/索引/函数/触发器/任务、套餐到期、精确存储规则、密钥轮换、备案/类目/隐私/模板、开发版上传和审核操作说明。每项证据须有最近7天内的复核时间和非空文件的SHA-256；任何缺失、过期、未通过或阻塞均拒绝。

证据文件不是自动生成的“通过声明”。截图、命令输出和人工真机记录必须真实对应目标版本，并由复核者逐项确认；脚本不能鉴别人为伪造的记录。不得为了通过而填写占位成功值。敏感原始证据留在被忽略的 `.release-evidence/`，提交报告只记录脱敏结论。

正式通知目标的切换须在最终验收后、正式上线前显式设置 `MINIPROGRAM_STATE=formal` 并重新读取验证；本轮开发验证继续使用 `developer`。共用环境的体验账号会受到切换影响，不能提前切换。
