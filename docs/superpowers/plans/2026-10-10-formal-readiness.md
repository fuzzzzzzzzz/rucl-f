日期：2026-10-10。范围来自用户已批准的“真机前能完成的任务”；不包括购买服务、切换正式通知、提交审核或正式发布。

## 设计与约束

- 正式客户端统一使用 `api`。旧 `recentReturnsPreview` 暂时保留兼容，不删除；本地改好不等于云端部署完成。
- 微信图片审核使用 `mediaCheckAsync` v2。提交返回 `trace_id` 只是排队；最终事件为 `wxa_media_check`，必须由可信接收端验真后才可接受。
- 当前官方消息推送文档只承诺客服消息的云函数接收。不能臆测图片审核可直接投递云函数，也不能信任客户端提供的 `pass` 或 `SOURCE`。
- 首次后台只读核实：云开发控制台 → 设置 → 其他设置 → 添加消息推送 → 消息类型 `event`，事件列表确实含 `wxa_media_check`。随后取得用户“允许”的明确确认，已保存并启用到 `mediaSafetyProbe` 的专用绑定；界面操作变为“停用 / 删除”。这仍不证明真实审核事件已投递。
- 已验证签名、解密和 AppID 的服务器安全模式回调是备选。先实现可测试的验真与状态转换组件；在稳定 HTTPS 接收端、有效隐私用途及真实回调缺失时，不部署、不标记完整图片审核已实现。
- 图片流程最终必须按上传凭证、文件和审核任务绑定；`pending/review/risky/error/expired` 均不能提供可使用的上传凭证或照片链接。旧文件不得无证据自动标为通过。
- 提审材料明确区分本地测试、云端回读、后台生效、手机验收；不伪造截图或 `passed` 清单。

## Task 1：可独立验证的审核接收基础

新增 `cloudfunctions/api/media-safety.js` 与 `tests/media-safety.test.js`。先写失败测试再实现：

1. 验证安全模式 `msg_signature`，要求配置完整、参数正确、有有限的新鲜度窗口，常量时间比较签名。
2. AES-256-CBC 解密微信消息，严格校验 32 字节 PKCS#7、消息长度、AppID，解析 JSON，拒绝未验真直接事件。
3. 只接受 `MsgType=event`、`Event=wxa_media_check`、`version=2` 的最终审核；数字 `errcode=0` 且明确 `pass` 才能通过，其他状态阻止使用。
4. 任务转换绑定既有非空 trace_id；同一结论重复投递幂等，冲突结论或过期任务不得变为通过。
5. 不记录明文、URL、密钥或用户身份；仅为纯组件，无新云函数、HTTP 路由、数据库迁移或线上开关。

验证：`npx vitest run tests/media-safety.test.js`、云端语法/Lint；规范复核后再代码质量复核。
