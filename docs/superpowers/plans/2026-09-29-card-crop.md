# Local card crop implementation plan

Goal: suggest a local red/white campus-card crop before OCR, requiring confirmation for every suggested crop.

Architecture: a pure bounded-resolution pixel detector returns a padded rectangular candidate, not an asserted card identity. A page-owned Canvas 2D adapter creates a temporary JPEG at no greater than source resolution. The found page displays the candidate with crop/original/cancel actions. No server, paid API, permissions, or cloud deployment changes.

Scope: this phase does not claim generic card recognition, precise segmentation, perspective correction, or OCR accuracy improvements. Multiple comparable candidates and missing/truncated lower panels fail closed to the original image. Unsupported canvas and preparation failures fall back without blocking existing OCR. Local images remain temporary and are not written to the album.

Tasks:

- [x] Add synthetic pixel tests for red/white card, blank background, non-neutral lower panel, competing cards, and boundaries.
- [x] Implement `miniprogram/shared/card-crop.ts`: connected red components plus lower neutral-panel check; bounded inputs and padded rectangle.
- [x] Add `miniprogram/services/local-card-crop.ts`: Canvas image loading, reduced detection, original-resolution crop, JPEG export, bounded deadline and no cloud calls.
- [x] Add found-page candidate confirmation and rejection; preserve lifecycle/duplicate-action safeguards. Test that no OCR runs before crop confirmation and rejected crop uses original.
- [x] Run detector on prior local sample images, visually inspect outputs, run tests/typecheck/lint.
- [ ] Confirm Canvas rendering/export and crop acceptance on an actual phone.

Acceptance: suggested crop never auto-submits; ordinary failure still permits original recognition; stale callbacks cannot replace newer photos; private pixels and paths are never logged. Device verification remains required before claiming runtime completion.

Local validation: 8 supplied images tested with the TypeScript detector via local Sharp decoding. Five screenshots produced visually reviewed candidates preserving identity text, two non-card screens returned no candidate, and the partly clipped original photo conservatively returned no candidate. This detector is intentionally not the Python perspective-warp prototype.

Verification: full verify gate passed with 486 tests; an additional stale-identity cancellation regression was then added and passed, followed by a full 487-test run, TypeScript and whitespace checks. No cloud functions were deployed and no OCR calls were made by these tests. Runtime preview remains separate from release upload.
