# 近期暖心归还

用户已确认两行动态设计，并明确要求直接完成实现，不重复请求方案确认。

## 展示

首页使用说明之后、黄色品牌卡片之前增加“近期暖心归还”。按真实完成时间倒序展示最近 30 天最多 5 条有效校园卡交还记录。不展示排名、数量竞争或示例人物。转交到官方点不等同于交还失主，本次只展示已经完成交还的 handovers。

每条第一行是装饰徽章、拾卡者公开称呼、经授权的部分学号、北京时间 `9月17日 12:36` 和“完成一次校园卡交还”；第二行轮换用户提供的五句暖心文案。使用米白底、黑边框、细分隔线，与现有页面风格一致。徽章不代表等级。

## 隐私

默认显示“一位热心同学”，不公开学号。账号设置增加匿名、部分姓名及部分学号、全名及部分学号三个方式；后两项必须分别说明公开范围并由本人主动确认。全名需要单独的明确同意，不继承感谢墙同意。仅从服务端已有本人资料生成公开称呼，学号始终掩码，不能信任客户端传入的姓名、学号或目标账号。

授权只适用于授权后完成的交还，不追溯公开旧记录。撤回后服务端下一次读取恢复匿名；页面重新显示时清空旧结果再请求，避免失败时残留旧身份。不能承诺撤回已经被其他人截图的内容。被封禁、删除中或身份更正中的用户不公开身份。返回字段不包括 OpenID、失主信息、照片、地点、原始学号和业务关联 ID。

## 兼容与边界

现有绑定资料只保存姓名摘要与脱敏姓名，不能恢复全名，也不等于学校官方认证。因此全名授权时由本人再次输入姓名，服务端必须验证其摘要与当前绑定姓名一致后才保存用于公开的姓名；弹窗明确说明这一用途。撤回或改为部分姓名时删除该公开姓名。不能直接相信客户端提供的姓名，更不能为未授权用户新增全名存储。

旧云函数不支持新动作时，只显示“动态暂不可用”并允许重试，不影响原有首页账号状态和功能。不改动现有业务完成流程，不新增收费服务，不写测试数据到线上，不自动部署、上传或发布。

## 验证

测试真实 handler 的授权隔离、默认匿名、掩码、全名单独同意、撤回、异常账号、真实完成状态、时间排序及上限；测试客户端日期格式、同意/取消/失败、旧后端及刷新清除行为。运行完整本地门禁并在模拟器检查实际页面。仅模拟数据的本地测试不能声称真实线上动态已接通。
