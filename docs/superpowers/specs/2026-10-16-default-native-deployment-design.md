# 默认部署配置与已验证审核方案对齐

## 目标与范围

用户已选择统一默认配置。仅调整本地部署配置、资源合同、校验测试和说明，避免日后按旧默认配置部署时关闭已经验证的新回调。此次不部署云函数、不执行资源 apply、不改线上权限或存储、不重试通知、不再次提交图片、不提审发布。

## 配置方案

- `cloudbaserc.json` 保留原有四个函数，并增加 `mediaSafetyCallback`。API 与回调共享 `cloudfunctions/api` 代码目录，入口分别为 `index.main` 和 `media-native-entry.main`；不新增重复代码包或依赖目录。
- API 和回调使用已验证的 native 模式、固定 AppID/环境 ID、服务端 `MEDIA_INTEGRITY_KEY` 占位符。沿用现有密钥，不生成、不轮换、不写入明文；API 原有三个业务变量保留，回调不获得这些变量。
- 原删除、识别、清理函数的资源、变量和定时器保持原样。HTTP 审核实现保留，但默认配置不再要求旧 TOKEN/AES 变量。
- 保留双目标配置 `cloudbaserc.native-callback.json` 供定点部署使用；测试要求其两个目标与默认配置相同，防止两套定义漂移。

## 权限及校验

资源合同纳入新回调，仅这个固定目标允许 `invoke=true`，并明确其平台回调用途和现有来源检查。未知函数继续默认拒绝；原客户端函数继续要求非匿名登录；后台任务继续拒绝客户端调用。校验器不得以通用例外允许其他函数开放。

部署包测试按显式代码目录解析共享包，继续检查实际依赖及入口。四个物理云函数包与五个部署目标必须区分，不降低存储、真机或发布门禁。

## 验收与恢复

先新增失败用例，再修改配置与校验器。验证新回调被完整覆盖，错误入口、错误身份/模式、任意额外放行和配置漂移会失败；运行完整本地检查及 Windows/Linux CI。仅提交已验证变更，任何失败如实记录。恢复只需还原此次本地变更，不执行云端恢复操作，因为本轮不进行线上写入。

## 自审

本方案无占位需求；范围仅限部署描述和校验，不宣称解决旧通知、清理函数部署或正式存储切换。用户已完成的隐私、UGC 和密钥重置不重复办理；开发者工具页面检查不代替后台用途正文核对或真机验收。
